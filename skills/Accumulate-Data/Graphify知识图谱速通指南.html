1
一句话理解
Graphify 就像给你的 AI 编程助手装了一颗"项目大脑"——它先把整个代码库的文件、函数、调用关系编织成一张可查询的知识网络，之后 AI 每次提问只需要"看图找路"，而不用把所有文件再读一遍。

类比来说：传统方式相当于每次想找东西都要翻遍整个文件柜；Graphify 则是先给文件柜建了一份详细的索引地图，之后找什么直接查地图即可。

2
为什么需要它？

过去怎么解决

AI 编程助手（如 Claude Code、Cursor）在理解大型代码库时，传统方式是：

  • 全文塞入上下文：把尽可能多的源代码文件直接放入 LLM 的上下文窗口
  • 逐文件搜索：通过 grep / 正则搜索关键字，找到文件后再读取
  • 向量检索：使用 Embedding + 向量数据库做语义相似度搜索
  • 手动维护文档：用 Markdown Wiki 记录项目结构，靠人工保持同步

存在哪些问题

问题维度具体痛点
Token 消耗大型项目（500-5000 文件）每次查询约消耗 70,000 Token，成本高昂
上下文丢失LLM 上下文窗口有限，无法一次性装下所有代码，关键关系容易被截断
关系理解弱grep 只能搜文本，无法理解函数调用链、模块依赖等结构化关系
向量检索局限需要额外维护向量数据库，语义相似不等于代码逻辑相关，且数据需离机
知识不可持久每次会话都要重新分析，跨会话无法复用之前的理解成果
多模态割裂代码、文档、PDF、图片分散在不同工具中，无法统一检索和关联

为什么出现该技术

核心洞察：AI 编程助手缺的不是更多上下文，而是一张"提前画好的代码地图"。Graphify 用预构建知识图谱 + 图遍历查询替代逐文件搜索和向量检索，将"每次查询都读全文"变为"一次构建、多次查图"，从根本上解决 Token 消耗和关系理解问题。

2026 年 4 月由开发者 Safi Shamsi 发布，灵感来源于 Andrej Karpathy 公开的个人知识库工作流——将所有原始材料"编译"成结构化知识库。Graphify 将这一思路从扁平 Markdown Wiki 推进到了结构化知识图谱 [1][2]。

3
什么是它？

简单定义

Graphify 是一款开源、本地优先的多模态知识图谱构建工具，能将任意文件夹中的代码、文档、PDF、图片、音视频等材料自动解析为结构化知识图谱。图谱持久化存储在本地，支持跨会话查询和增量更新，常作为 Claude Code、Cursor 等 AI 编程助手的核心插件使用 [1]。

通俗类比

想象你搬进一栋新房子（新项目代码库）。传统 AI 助手每次帮你找东西，都要逐个房间翻箱倒柜。Graphify 则是先花时间画一张详细的"房屋地图"——标注了每个房间的用途、物品之间的关联、哪些房间相通。之后你问"我的钥匙在哪"，它直接查地图告诉你路线，而不用重新搜遍整栋房子。

核心组成

AST 结构提取引擎
基于 tree-sitter 解析 36 种编程语言的语法树，零 LLM 成本提取函数、类、调用关系
语义提取通道
对文档、PDF、图片进行 LLM 语义分析，提取概念和关系，支持 8 种模型后端
Leiden 社区发现
用图拓扑算法自动识别模块聚类和隐藏耦合，无需向量数据库
三级置信度标签
每条关系标注 EXTRACTED / INFERRED / AMBIGUOUS，区分确定性和推断结果
持久化图谱存储
graph.json 本地存储，跨会话复用，支持 SHA256 缓存的增量更新
交互式可视化
生成 graph.html 交互式图谱，支持点击节点、搜索、按社区过滤

它是怎么工作的？

Graphify 采用三趟提取（Three-Pass Extraction）策略，分阶段处理不同类型的材料 [4]：

输入：项目文件夹（代码 / 文档 / PDF / 图片 / 音视频）
↓
第一趟：AST 结构提取（本地，零 API 成本）
↓
第二趟：音视频本地转录（faster-whisper）
↓
第三趟：AI 语义提取（文档/PDF/图片，需 API）
↓
图构建：实体与关系合并入 NetworkX 图谱
↓
社区发现：Leiden 算法划分子系统
↓
分析报告：核心节点、意外连接、建议问题
↓
输出：graph.html + GRAPH_REPORT.md + graph.json

每一步说明

  • AST 结构提取：使用 tree-sitter 解析 36 种语言的语法树，提取类、函数、变量、导入、调用图、docstring。完全本地运行，结果确定性，零 LLM 成本
  • 音视频转录：使用 faster-whisper 本地转录，数据不离机。使用领域感知提示词提高专业术语准确率
  • AI 语义提取：对非代码材料进行并行语义分析，提取概念、关系和设计原理。支持 Claude、GPT-4、Gemini、DeepSeek、Kimi、Ollama 等 8 种后端
  • 图构建：将三趟提取的实体和关系合并入统一的 NetworkX 知识图谱，每条边标注三级置信度
  • 社区发现：Leiden 算法（优于 Louvain）自动将图划分为子系统，1000 文件 + 10000 边规模下数秒收敛
  • 输出：生成交互式可视化图谱、智能分析报告和持久化图谱数据三份文件

怎么使用它？

7.1 最简单使用方式

前置要求：Python 3.10+，任一支持的 AI 编程助手

# 1. 安装 graphify（PyPI 包名为 graphifyy） pip install graphifyy # 2. 安装到你的 AI 编程助手 graphify install # 3. 在 AI 编程助手中输入命令构建图谱 /graphify .
Claude Code Cursor Codex OpenCode Gemini CLI GitHub Copilot ...共 20+ 平台

7.2 常用命令

命令作用
/graphify .为当前目录构建知识图谱
/graphify ./my-project指定目录构建
/graphify . --mode deep深度模式，更激进的推断边提取
/graphify . --update增量更新，只处理变更文件
/graphify . --cluster-only仅重新聚类，不重新提取
/graphify query "..."对图谱进行语义查询
/graphify path "A" "B"查找两个节点间的依赖路径
/graphify stats查看图谱统计信息

7.3 企业应用方式

大型代码库维护
快速定位调用链、依赖冲突、架构冗余，支持重构决策与代码审计
AI 编程助手增强
为 Claude Code/Cursor 注入结构化理解，回答架构/流程/模块关系问题更精准
多模态项目管理
统一管理代码、设计图、会议录、论文，构建项目级知识网络
团队知识协作
将 graph.json 纳入版本控制，导出 Obsidian/Wiki，新成员快速上手
PR 审查辅助
自动分析 PR 对图谱的影响，可视化变更波及范围，预防冲突
CI/CD 集成
Git 钩子自动增量重建图谱，CI 流水线监控项目复杂度变化

7.4 技术实现要点

  • 解析引擎：tree-sitter（36 种语言 AST）、faster-whisper（音视频转录）
  • 图数据结构：NetworkX 知识图谱，节点 = 实体，边 = 关系
  • 社区发现：Leiden 算法（优于 Louvain），跨运行稳定
  • LLM 后端：支持 Claude、GPT-4、Gemini、DeepSeek、Kimi、Ollama 等 8 种
  • 缓存机制：SHA256 文件级缓存，增量更新只处理变更
  • 输出格式：graph.html（可视化）、GRAPH_REPORT.md（报告）、graph.json（持久化数据）

实战经验和常见问题
常见问题原因分析解决方式
pip install graphify 报错 PyPI 包名冲突，正式包名为 graphifyy 使用 pip install graphifyy 或 pipx install graphifyy
安装后命令不存在 Scripts 目录未加入 PATH 执行 pip show graphifyy 找到路径，手动加入 PATH
Claude API key not found / 401 未配置 ANTHROPIC_API_KEY 环境变量 设置 $env:ANTHROPIC_API_KEY="sk-xxx"（PowerShell）
构建超时 / 速率限制 大项目语义提取阶段 LLM 调用量大 使用 --update 增量模式；分批处理；切换本地模型 Ollama
图谱关系不准确 INFERRED/AMBIGUOUS 边置信度低 查看 GRAPH_REPORT.md 中的置信度标签，人工审核 AMBIGUOUS 边
图谱过大加载慢 超大项目节点数过多 使用 --lang 限定语言，--exclude 排除测试/日志文件
图谱与代码不同步 代码变更后未更新图谱 配置 Git 钩子自动触发 --update；CI 集成定期刷新
多模态提取失败 图片/PDF 格式特殊或 LLM 后端不支持 确认 LLM 后端支持视觉能力；分类型单独处理

容易混淆的技术
技术核心区别适用场景
Graphify 代码/文档多模态 → 知识图谱，图遍历查询，零向量库依赖，本地优先 大型代码库理解、AI 编程助手增强、项目架构分析
RAG + 向量数据库 文档 → Embedding → 向量检索，需要向量数据库，语义相似度匹配 文档问答、知识库查询、非结构化文本检索
Karpathy Wiki 工作流 材料 → Markdown Wiki，扁平文档集合，关系靠文本链接隐式表达 个人知识管理、轻量笔记整理（Graphify 是其图谱化升级版）
CodeGraph TypeScript 项目，专注于代码关系图谱，功能较单一 纯代码依赖分析，不需要多模态支持的场景
传统静态分析工具 代码质量检查、复杂度评估，输出文本报告，不构建图谱 代码质量门禁、安全漏洞扫描
Supermemory AI 记忆层方案，侧重对话上下文持久化，非代码结构化 对话记忆增强，非项目级代码理解
选型建议：需要理解大型代码库结构 + AI 编程助手增强 → Graphify；需要文档问答检索 → RAG；需要个人知识管理 → Karpathy Wiki；只需代码依赖分析 → CodeGraph。

当前发展情况和趋势

当前阶段

快速成长期 YC S26 孵化 88K+ Stars MIT 开源协议

2026 年 4 月发布，短时间内获得极高人气。截至 2026 年 7 月，GitHub Stars 超 88K，PyPI 下载量在发布 26 天内突破 45 万次，由 Y Combinator S26 批次孵化的 Graphify Labs 维护 [3][4]。

当前应用方向

  • AI 编程助手增强：作为 Claude Code、Cursor 等平台的核心 Skill 插件
  • 大型代码库维护：企业级项目的架构理解和重构决策支持
  • 多模态知识管理：统一管理代码、文档、设计图、论文的项目级知识网络
  • 团队协作与新人上手：将 graph.json 纳入版本控制，降低知识传递成本

未来趋势

  • 更多 AI 平台集成：从当前 20+ 平台继续扩展，成为 AI 编程助手的标准"记忆层"
  • 实时图谱更新：从手动增量更新向文件保存即触发的实时同步演进
  • 图谱质量自动化：AMBIGUOUS 边的自动消歧和人工审核工作流
  • 跨项目知识关联：多个项目的图谱互联，构建组织级知识网络
  • 与 Agent 深度融合：知识图谱作为 Agent 的持久记忆层，支持自主决策
