📚 九、今天最值得学习的三个知识点

知识点 1：MCP 协议无状态核心设计

为什么需要Agent 需要连接外部工具和数据源，每家 SDK 写一套适配成本高昂

是什么Model Context Protocol 终版规范实现无状态核心，每个请求自包含完整上下文，不再需要服务端维护会话状态

怎么使用通过 langchain-mcp-adapters 或原生 SDK 挂载多个 MCP Server，Agent 自动发现并调用工具

最佳实践团队内部工具沉淀为标准 MCP Server，跨项目跨框架共享

容易踩坑无状态设计要求每个请求携带完整上下文，长上下文需注意 token 成本

推荐资料MCP 终版规范文档、langchain-mcp-adapters 官方文档

学习时间15 分钟即可掌握核心概念

知识点 2：KV Cache 内存层级优化

为什么需要Agent 场景中 System Prompt、工具定义等前缀高度重复，传统框架浪费 70%+ Prefill 算力

是什么PagedAttention 将 KV Cache 分页管理（显存浪费降至 <4%）；RadixAttention 用基数树自动复用共享前缀（Prefill 提速 5-10x）

怎么使用vLLM 开启 --enable-prefix-caching；SGLang 默认启用 UnifiedRadixTree

最佳实践Agent/RAG 场景优先选择 SGLang；需要最新模型支持选 vLLM

容易踩坑vLLM 0.26 和 SGLang 0.5.16 都有 breaking changes，升级前需阅读 release notes

推荐资料vLLM 0.26 / SGLang 0.5.16 Release Notes

学习时间15 分钟即可掌握核心概念

知识点 3：多智能体跨会话协同

为什么需要单 Agent 孤立工作无法处理复杂项目，多任务并行时上下文同步靠人工复制粘贴效率极低

是什么Claude Code 跨会话消息传递：通过 ListAgents 发现可用 Agent，SendMessage 发送消息，支持自动检测并主动通知

怎么使用对 Claude 说"把这个 API 接口修改通知给 test-session"，自动整理摘要并发送

最佳实践按功能域划分会话（前端/后端/测试），利用自动通知机制减少人工协调

容易踩坑跨机回复只能回复不能发起；接收方在工具调用间隙读取消息，不会中断正在运行的工具

推荐资料Claude Code 官方文档 - Cross-session Messaging

学习时间15 分钟即可掌握核心概念

⚠️ 十一、风险提醒

风险 1：Kimi-K2.5 API 将于 8 月 31 日下线

影响范围：使用 Kimi-K2.5 或 moonshot-v1 系列模型的所有项目

建议：立即规划迁移至 Kimi-K3 / kimi-2.6 / Kimi-K2.7-Code 系列，预留测试时间

风险 2：前沿模型网络安全"越界"能力

影响范围：使用 GPT-5.6-Sol / Mythos 5 等前沿模型的企业，尤其在网络安全相关场景

建议：建立 AI 使用安全边界，对 Agent 行为实施全局监控，评估思维链审查机制

风险 3：AutoGen 框架维护模式

影响范围：所有基于 AutoGen 的 Agent 项目

建议：预算迁移计划，迁移至 Microsoft Agent Framework 或 LangGraph。维护模式下安全补丁继续，但新模型/协议适配需自行维护

风险 4：vLLM 0.26 / SGLang 0.5.16 破坏性变更

影响范围：使用 vLLM 或 SGLang 的推理服务

建议：vLLM 移除了 TeleChat/Persimmon/Fuyu 模型支持；SGLang 移除了 QServe/FBGEMM FP8，NVFP4 需要 FlashInfer。升级前务必阅读 release notes 并锁定版本

风险 5：DeepSeek API 拟提价

影响范围：使用 DeepSeek API 的应用和团队

建议：重新评估调用成本，考虑混合部署策略（开源模型私有化 + API 补充），关注官方定价公告

风险 6：Astra 模型安全审查不确定性

影响范围：依赖 OpenAI 最新模型的下游应用和产品规划

建议：不要将产品路线图绑定到未发布模型，保持多模型供应商策略，关注 OpenAI 官方安全审查进展
