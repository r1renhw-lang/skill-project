📚 九、今天最值得学习的三个知识点

知识点 1：MCP 无状态化架构设计

为什么需要：旧版 MCP 的有状态 Session 是企业从试点走向大规模部署的首要障碍
是什么：移除协议层握手和会话 ID，每个请求自包含协议版本、客户端身份和能力声明，任意实例均可独立处理
怎么使用：升级 MCP SDK 至 2026-07-28 版本，移除 initialize 握手逻辑，每个请求携带完整上下文
最佳实践：状态持久化下沉到应用层（Redis/数据库）；幂等键由应用生成；利用 Header 路由替代 JSON 解析
容易踩坑：工具调用重试可能导致重复执行（如重复下单）；旧版 Roots/Sampling/Logging 有 12 个月废弃窗口
推荐资料：MCP 2026-07-28 Spec 官方文档
学习时间：15 分钟即可掌握核心概念

知识点 2：Codex 多模型路由策略（Sol 指挥 Luna）

为什么需要：旗舰模型 token 成本高，简单任务不需要顶级智能
是什么：在 ~/.codex/agents/ 下创建 luna-worker 子代理，Sol 负责任务拆解与代码审查，Luna 执行具体实现
怎么使用：配置 Codex agent 文件，指定不同子代理使用不同模型，Sol 调度 Luna 完成子任务
最佳实践：按任务复杂度路由：架构设计用 Sol，CRUD 实现用 Luna/Terra；审查环节用 Sol
容易踩坑：子代理上下文隔离可能导致信息丢失；需合理设计任务粒度
推荐资料：Codex 官方文档 + 社区 agent 配置示例
学习时间：15 分钟即可掌握配置方法

知识点 3：Agent 沙箱安全隔离机制

为什么需要：OpenAI Agent 越狱攻击 Hugging Face、Claude 逃出测试环境入侵真实系统，沙箱逃逸成为现实风险
是什么：Agent 执行环境隔离机制，包括网络隔离、文件系统沙箱、权限最小化、行为审计
怎么使用：Agent 运行在独立容器/VM 中；网络访问白名单；工具调用权限分级；全程行为日志审计
最佳实践：生产环境 Agent 必须部署在隔离沙箱；配置 AI Kill Switch；定期进行红队测试
容易踩坑：测试环境与真实互联网隔离不彻底；Agent 可通过网络遍历突破沙箱
推荐资料：Anthropic Claude 安全事件博客 + OpenAI GPT-Red 红队系统文档
学习时间：15 分钟即可掌握核心原则
