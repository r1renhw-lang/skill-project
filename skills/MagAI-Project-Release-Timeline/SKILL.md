# Release Timeline

## Overview

根据用户输入的项目发布信息（版本号、发布内容、负责人、发布日期/周期等），
自动生成一个美观的、可在浏览器直接打开的 HTML 时间线页面。
页面采用垂直时间线布局，支持多项目追踪、版本卡片展示、筛选与搜索等功能。

## When to Use

- 用户提供了版本号、发布内容、负责人等发布信息，需要生成时间线
- 用户提到"发布时间线"、"版本记录"、"release timeline"、"迭代记录"等关键词
- 用户需要复盘或汇报某个项目的发布历程
- 用户需要追踪多个项目的发布节奏与内容

## Input Format

用户输入的发布信息可以是非结构化的自然语言，也可以是结构化数据。
WorkBuddy 应从用户输入中提取以下字段：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| project | ✅ | 项目名称 | "企业微信待办助手" |
| version | ✅ | 版本号 | "v1.2.0" |
| date | ✅ | 发布日期 | "2026-08-10" |
| content | ✅ | 发布内容/更新说明 | "新增待办批量导入功能，修复消息链接参数丢失问题" |
| owner | ❌ | 负责人 | "任宏伟" |
| type | ❌ | 发布类型（major/minor/patch/hotfix） | "minor" |
| notes | ❌ | 备注 | "需关注测试环境网络问题" |

如果用户提供了多条发布记录，应全部解析并在时间线中展示。
如果用户未提供某些可选字段，在 HTML 中合理留空或标注"未指定"。

## Workflow

### Step 1: 解析输入数据

从用户输入中提取发布记录信息。支持以下输入形式：

**形式一：自然语言描述**
```
项目A在8月10日发布了v1.2.0，主要更新了批量导入功能，负责人是张三。
项目B在8月8日发布了v2.0，大版本升级，负责人是李四。
```

**形式二：结构化列表**
```
1. 项目: 企微待办助手 | 版本: v1.2.0 | 日期: 2026-08-10 | 负责人: 任宏伟 | 内容: 批量导入、链接修复
2. 项目: 邮件管理Skill | 版本: v0.3.0 | 日期: 2026-08-08 | 负责人: 任宏伟 | 内容: 初版邮件搜索功能
```

**形式三：JSON / 表格粘贴**
```json
[
  {"project": "项目A", "version": "v1.0", "date": "2026-07-01", "content": "初始版本", "owner": "张三"},
  {"project": "项目A", "version": "v1.1", "date": "2026-07-15", "content": "性能优化", "owner": "张三"}
]
```

### Step 2: 数据校验与补全

- 检查必填字段（project, version, date, content）是否齐全，缺失时向用户确认
- 日期格式统一为 `YYYY-MM-DD`
- 如果用户未指定 `type`，根据版本号自动推断：
  - `X.0.0` → major
  - `X.Y.0` → minor
  - `X.Y.Z` → patch
  - 包含 `hotfix`/`紧急` 关键词 → hotfix

### Step 3: 生成 HTML 时间线

使用 `assets/timeline-template.html` 模板生成最终 HTML 文件。

**生成规则：**

1. **文件命名**：`release-timeline-{YYYYMMDD-HHmmss}.html`，保存在用户工作目录下
2. **时间线排序**：按日期降序排列（最新发布在最上方）
3. **多项目支持**：如果包含多个项目，按项目分组展示，支持项目筛选
4. **版本类型标识**：不同类型用不同颜色的左侧色条标识
   - major → 红色 `#e74c3c`
   - minor → 蓝色 `#3498db`
   - patch → 绿色 `#2ecc71`
   - hotfix → 橙色 `#f39c12`
5. **搜索功能**：页面顶部提供搜索框，可按项目名/版本号/内容实时筛选
6. **响应式布局**：适配桌面和移动端

**HTML 页面结构：**

```
┌───────────────────────────────────────┐
│  📋 发布时间线                          │
│  [搜索框]  [项目筛选 ▼]  [类型筛选 ▼]   │
├───────────────────────────────────────┤
│  ● 2026-08-10  v1.2.0  [minor]        │
│  │  项目: 企微待办助手                   │
│  │  负责人: 任宏伟                       │
│  │  内容: 批量导入功能、链接参数修复       │
│  │                                      │
│  ● 2026-08-08  v0.3.0  [minor]        │
│  │  项目: 邮件管理Skill                  │
│  │  负责人: 任宏伟                       │
│  │  内容: 初版邮件搜索功能                │
│  ...                                    │
└───────────────────────────────────────┘
```

### Step 4: 交付结果

- 使用 `preview_url` 工具在浏览器中预览生成的 HTML
- 使用 `deliver_attachments` 工具将 HTML 文件交付给用户
- 在回复中简要说明生成了多少条记录、涉及哪些项目

## HTML 模板规范

生成的 HTML 文件必须满足以下要求：

### 技术要求
- **单文件**：所有 CSS/JS 内联，不依赖外部资源（可使用 CDN）
- **编码**：UTF-8，确保中文正常显示
- **零依赖运行**：双击即可在浏览器打开

### 视觉规范
- **背景色**：`#f8f9fa`（浅灰）
- **卡片背景**：`#ffffff`（白色）
- **主文字色**：`#2c3e50`
- **辅助文字色**：`#7f8c8d`
- **字体**：`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`
- **时间线竖线**：`#e0e0e0`，宽度 2px
- **时间线节点**：圆形，直径 14px，颜色对应版本类型
- **卡片圆角**：8px
- **卡片阴影**：`0 2px 8px rgba(0,0,0,0.08)`

### 交互功能
- 搜索框：实时筛选（按项目名、版本号、内容匹配）
- 项目筛选下拉框：多项目时显示
- 类型筛选下拉框：可按 major/minor/patch/hotfix 筛选
- 卡片悬停效果：阴影加深，轻微上移

## Usage Examples

### Example 1: 单项目多版本

**用户输入：**
> 帮我生成发布时间线：
> - 企微待办助手 v1.0.0，2026-07-01发布，初始版本，负责人任宏伟
> - 企微待办助手 v1.1.0，2026-07-20发布，新增待办CRUD和提醒功能，负责人任宏伟
> - 企微待办助手 v1.2.0，2026-08-10发布，批量导入和链接修复，负责人任宏伟

**预期行为：** 解析3条记录，生成HTML时间线，按日期降序排列，preview预览 + 交付HTML文件。

### Example 2: 多项目混合

**用户输入：**
> 生成发布时间线，包含以下信息：
> 1. 企微待办助手 v1.2.0 8月10日 任宏伟 批量导入功能
> 2. 邮件管理Skill v0.3.0 8月8日 任宏伟 邮件搜索初版
> 3. 企微待办助手 v1.1.0 7月20日 任宏伟 待办CRUD和提醒
> 4. 邮件管理Skill v0.1.0 7月5日 任宏伟 项目初始化

**预期行为：** 解析4条记录，按项目分组+日期降序，支持项目筛选下拉框。

### Example 3: 自然语言输入

**用户输入：**
> 我们项目A在7月1号发了1.0版本，是第一个正式版本，张三负责的。然后7月15号又发了一个1.1的小版本更新，主要是做了性能优化。最近8月10号发了个紧急修复版本1.0.1，修了一个登录bug，李四处理的。

**预期行为：** 从自然语言中提取3条记录，自动推断版本类型（major/minor/hotfix），生成时间线。
